Comments let you have a conversation attached directly to a file, so feedback lives
next to the thing it's about instead of scattered across email or chat.

## Threads and replies

Comments are organized as **threads**. Start a new thread to raise a point, and
**reply** underneath to keep a discussion together. Replies nest, so a long
back-and-forth stays readable.

## Mentions

Type **@** and a name to **mention** someone. Mentioned users are notified so they
can jump straight to the relevant thread.

## Editing and deleting

You can **edit** or **delete** your own comments. An edited comment is marked so the
history stays honest.

## Requesting a review

Use **⚑ Review** to request that someone review the document. This signals the
reviewer that their input is wanted and tracks the request alongside the discussion.

### The Reviews inbox

Review requests are collected in a **Reviews** inbox so nothing gets lost, split into
**Awaiting your review** (requests assigned to you) and **Requested by you** (ones you
opened, with their current status and outcome). From a request awaiting you, you can:

- **Acknowledge** it, to signal you've picked it up;
- **Approve** it; or
- **Request changes**.

Each entry links straight to the file — opening it on the relevant discussion thread —
so you can review in context and reply where the conversation already is.

## Working together in real time

The discussion panel has a small, focused set of live features that make
collaborating in the moment feel immediate — without turning it into a full
co-editing tool:

- **See who else is here.** While others have the same file's comments open, a
  "👁 N here" indicator shows how many people are viewing alongside you; hover it to
  see their names. You aren't counted in your own roster.
- **Comments update live.** New comments, edits, and deletions from other people
  appear in the open panel as they happen — no refresh needed — and a thread someone
  resolves updates on the spot. A comment that changes briefly highlights so you
  notice it.

These features are intentionally **limited and strategic**: they work only while the
comment panel is open on a file, and there are deliberately no typing indicators or
global "who's online" surface. Live sync is also an **enhancement** — if the live
connection isn't available, comments still work normally and you'll simply see
updates the next time the panel loads. Live updates respect permissions just like
everything else: only people who can read the file take part, and if someone's
access is removed mid-session, updates stop reaching them.

## Where comments appear

The discussion window opens for **any** file — including ones that can't be
previewed (for example a 3D model that failed conversion). When you're viewing a CAD
or BIM model, the comments panel can be docked to the **side** or **bottom** of the
viewer, or minimized to the title bar, so you can discuss the model while looking at
it.

## Who can comment

Commenting follows the file's permissions — see
[how permissions (ACLs) work](#acl-basics). If you can read a file, you can follow
its discussion; posting may require additional access depending on how the item is
configured.
